Battle of the algorithms

Du Sautoy stages a head-to-head: Bubble Sort vs Merge Sort on a large dataset. Bubble sort — compare adjacent pairs, swap if out of order, largest "bubbles" to the end each pass — is simple but slow. Merge sort — John von Neumann's divide-and-conquer: split in half, sort each half, merge — is guaranteed fast even on large data. The programme also tours Quick Sort, Shell Sort, Selection Sort, Insertion Sort and asks: which is the "best" sort? Answer: there is no single best — it depends on data size, memory, stability, and whether data is nearly sorted.

Bubble Sort (1:55) — adjacent compare-and-swap. After pass k, the k largest are in place. Simple, stable, in-place, but O(n²).
Merge Sort (1:23) — split, sort halves, merge with ≤ to stay stable. O(n log n) guaranteed, O(n) extra space.
Best Sort (2:52) — Bubble vs Merge plus Quick / Shell / Select / Insert. No universal winner.

The basics

The vocabulary your 1st evaluation tests — plus Day 1–2 language.

Algorithm

Finite, unambiguous steps: input → output. Must terminate, must be precise enough to follow on paper (Rubik's moves, number cards). Example from class: "set max to 0; for each x: if x > max, max ← x".

Algorithm language

procedure, ← / := assignment, if / for / while / repeat / return. Fibonacci example in handout uses x:=0; y:=1; for i:=1 to n−1: z:=x+y; x:=y; y:=z.

Comparison sort

Orders by pairwise comparisons. Decision-tree lower bound Ω(n log n). Bubble, selection, insertion, merge, quick, heap, shell.

Non-comparison sort

Uses key structure (integer range, digits) for O(n+k) linear time: counting, radix, bucket. Only works on restricted keys.

Stable

Equal keys keep original order. Bubble / insertion / merge / counting / radix (yes); selection / quick / heap / shell (no, standard). Use > not ≥ to stay stable.

In-place

O(1) extra (bubble, selection, insertion, shell, heap) or O(log n) stack (quick). Out-of-place: merge O(n), counting O(k).

Adaptive / Online

Adaptive = faster on nearly sorted (bubble+flag O(n), insertion O(n), Timsort). Online = handles stream (insertion).

Big-O

Growth as n→∞. Same Big-O ≠ same speed — constants, cache, branches decide. That's why micro-optimizations matter.

Rubik's link

Day 1: give algorithm + input + output ("provide the algorithm, input and output"). Tests: does it work? Is it ambiguous? Same test applies to sorts.

Euclid's GCD — Algorithm 1 (mod) vs Algorithm 2 (subtractive)

ALG 1 (mod): function gcd(a, b) while b ≠ 0 t := b; b := a mod b; a := t return a ALG 2 (subtractive): function gcd(a, b) while a ≠ b if a > b: a := a − b else: b := b − a return a
SimilarityDifference
AnswerBoth compute GCD(a,b); both loop until a termination condition; both preserve gcd(a,b)=gcd(b,a mod b)=gcd(a−b,b); same output on all positive inputs.ALG 1 uses division remainder — jumps many subtractions at once, O(log min(a,b)) steps. ALG 2 uses repeated subtraction — one subtraction per loop, O(max(a,b)) steps in the worst case. Tiles demo: mod removes a whole strip; subtractive peels one square row at a time.

Trace gcd(48,18)=6: Mod: (48,18)→(18,12)→(12,6)→(6,0) = 3 loops. Subtractive: 48−18=30, 30−18=12, 18−12=6, 12−6=6, 6=6 stop = 4 subtractions (worse gap explodes e.g. gcd(1000,1) = 1 mod step vs 999 subtractions).

Python — both versions
def gcd_mod(a, b):
    while b != 0:
        t = b
        b = a % b
        a = t
    return a

def gcd_sub(a, b):
    while a != b:
        if a > b:
            a = a - b
        else:
            b = b - a
    return a

print(gcd_mod(48, 18), gcd_sub(48, 18))  # 6 6

Computing Powers — naive (×n) vs fast (halve / subtract-one)

ALG 1 (naive): result=1; multiply by x, n times. O(n) mults. ALG 2 (fast): write n; while last≠1: if even halve it, if odd subtract 1. Start result=x; walk list backwards: "half" → square, "one less" → ×x. O(log n) mults.
SimilarityDifference
AnswerBoth compute xⁿ for n≥1; both iterative; same result; both multiply-only.ALG 1 does n−1 multiplications (linear). ALG 2 does O(log n) via exponentiation-by-squaring (uses binary expansion of n). ALG 2 builds an auxiliary list and walks it backwards; ALG 1 needs no extra structure.

Trace 2¹⁰: Naive = 9 mults. Fast: list 10→5→4→2→1; backwards from x=2: half→square (2²=4), one-less→×2 (8), half→square (64), half→square (1024) = 4 ops.

Python — both versions (clean + runnable)
def power_naive(x, n):
    r = 1
    for _ in range(n):
        r *= x
    return r

def power_fast(x, n):
    # exponentiation by squaring — O(log n)
    # mirrors handout: halve when even, subtract-one (×x) when odd
    r, base, exp = 1, x, n
    while exp > 0:
        if exp % 2 == 1:
            r *= base
        base *= base
        exp //= 2
    return r

# handout trace helper: show the halve/subtract-one list for n
def power_list(n):
    seq = [n]
    while seq[-1] != 1:
        seq.append(seq[-1] // 2 if seq[-1] % 2 == 0 else seq[-1] - 1)
    return seq

print(power_naive(2, 10), power_fast(2, 10))  # 1024 1024
print(power_list(10))  # [10, 5, 4, 2, 1] — walk back: square, ×x, square, square

Bubble Sort — 4 variants: similarities & differences + code

A1: while swapped and L<N-1: swapped=false; for i=N-1 downto L+1: if A[i]<A[i-1] swap; L++ A2: repeat N-1 times: for i=0..N-2: if A[i]>A[i+1] swap A3: for I=0..N-2: for J=0..N-2: if A[J]>A[J+1] swap (fixed bounds, no shrink) A4: cocktail: do { swapped=false; forward pass 0..n-2; if !swapped break; swapped=false; backward pass n-2..0 } while swapped
VariantDirectionEarly exit?Bound shrinks?Notes
A1 (L-bound)Right→left (small bubbles left)Yes (swapped flag)Yes (L++)Adaptive O(n) best; fewest passes of the four on sorted input
A2 (textbook)Left→right (large bubbles right)NoNoAlways N-1 passes, O(n²) even if sorted
A3 (double-for)Left→rightNoNo (0..N-2 both loops)Same as A2 but for-loop form; compares already-sorted tail every pass — most wasted work
A4 (cocktail shaker)Both (forward + backward)YesImplicitly both endsFixes "turtles" (small values at end take n passes in one-directional bubble); best on bidirectional disorder

Similarity (all four): adjacent compare-and-swap only; same sorted result; in-place O(1); stable if comparison is strict > (not ≥); worst-case O(n²) comparisons+swaps; after pass k at least k elements are final.

Difference to write on evaluation: pick any one — e.g. "A1 stops early via swapped flag and shrinks the unsorted region with L, so sorted input costs O(n); A2/A3 have no flag and always do (N−1)² comparisons" — or "A4 passes in both directions while A2 passes left-to-right only".

Python — Day 4 starter completed (do/while + for version)
# Day 4 starter pseudocode completed:
# do { swapped=false; for i=1..last_unsorted: if left>right swap, swapped=true } while swapped

def bubble_sort(a_list):
    n = len(a_list)
    while True:                       # do
        swapped = False
        for i in range(1, n):         # i = 1 .. index_of_last_unsorted
            if a_list[i-1] > a_list[i]:
                a_list[i-1], a_list[i] = a_list[i], a_list[i-1]
                swapped = True
        n -= 1                        # tail is sorted
        if not swapped:               # while swapped
            break
    return a_list

def other_bubble_sort(a_list):
    # A2/A3 textbook: fixed N-1 passes, no flag
    n = len(a_list)
    for _ in range(n - 1):
        for i in range(n - 1):
            if a_list[i] > a_list[i+1]:
                a_list[i], a_list[i+1] = a_list[i+1], a_list[i]
    return a_list

def cocktail_sort(a_list):
    # A4
    n = len(a_list)
    swapped = True
    while swapped:
        swapped = False
        for i in range(n - 1):
            if a_list[i] > a_list[i+1]:
                a_list[i], a_list[i+1] = a_list[i+1], a_list[i]
                swapped = True
        if not swapped:
            break
        swapped = False
        for i in range(n - 2, -1, -1):
            if a_list[i] > a_list[i+1]:
                a_list[i], a_list[i+1] = a_list[i+1], a_list[i]
                swapped = True
    return a_list

a = [5, 4, 6, 2, 4, 6, 7, 8, 1]
print(bubble_sort(a[:]))          # [1, 2, 4, 4, 5, 6, 6, 7, 8]
print(other_bubble_sort(a[:]))    # same
print(cocktail_sort(a[:]))        # same

Selection Sort — out-of-place vs in-place

OUT-OF-PLACE: sorted←[]; repeat n: min←first of list; scan rest for smaller; remove min; append to sorted. IN-PLACE (visualgo): repeat n-1: min←first unsorted; scan unsorted for smaller; swap min with first unsorted.
SimilarityDifference
AnswerBoth select the minimum of the unsorted region each pass; both do ~n²/2 comparisons, n−1 selections; both Θ(n²) time; neither is adaptive.Out-of-place builds a second list (O(n) extra, destroys/consumes input via remove); in-place swaps within the same array (O(1) extra, input preserved as sorted array). Out-of-place does no swaps (remove+append); in-place does ≤n−1 swaps. Typical in-place swap version is unstable; remove+append can preserve stability for equal keys if scan uses < strictly.
Python — both versions (completes Day 5 starter)
def selection_sort_out_of_place(a_list):
    work = a_list[:]          # don't destroy caller until done
    sorted_list = []
    while work:
        m = 0
        for i in range(1, len(work)):
            if work[i] < work[m]:
                m = i
        sorted_list.append(work.pop(m))
    a_list.clear()
    a_list.extend(sorted_list)
    return a_list

def selection_sort(a_list):   # in-place (visualgo)
    n = len(a_list)
    for i in range(n - 1):
        m = i
        for j in range(i + 1, n):
            if a_list[j] < a_list[m]:
                m = j
        a_list[i], a_list[m] = a_list[m], a_list[i]
    return a_list

numbers = [8, 8, 18, 13, 36, 0, 2, -2, -5]
print(selection_sort_out_of_place(numbers[:]))  # [-5, -2, 0, 2, 8, 8, 13, 18, 36]
print(selection_sort(numbers[:]))               # same

Insertion Sort (Visualgo algorithm) + code

mark first element sorted for each unsorted X: 'extract' X for j = lastSorted downto 0: if A[j] > X: shift A[j] right by 1 else: break and insert X

Stable, in-place, adaptive O(n) best / O(n²) worst, online. Shifts (not swaps) — one write per moved element plus final insert.

Python
def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

print(insertion_sort([5, 4, 6, 2, 4, 6, 7, 8, 1]))
# [1, 2, 4, 4, 5, 6, 6, 7, 8]

Counting Sort — base + Q1 (negatives / 6000–7000) + Q2 (money)

Base (non-negative ints): counting array size max+1; count occurrences; walk counters low→high, emit value counter times. O(n+k). Code in Day 6 - countingSortLesson.py.

Q1 Scenario 1 — negatives: value can't index directly. offset = min(list), spread = max − min, size = spread+1, index = element − offset, restore with value = index + offset. Scenario 2 (6000–7000): same offset code kills the 0–5999 waste: size drops from 7001 to 1001. Reuse Scenario-1 code verbatim.

Python — Q1 offset version
def counting_sort_offset(a):
    if not a:
        return []
    mn, mx = min(a), max(a)
    spread = mx - mn
    cnt = [0] * (spread + 1)
    for x in a:
        cnt[x - mn] += 1
    out = []
    for i, c in enumerate(cnt):
        out.extend([i + mn] * c)
    return out

print(counting_sort_offset([4, -2, 0, -2, 7, 6005, 6001, 7000][:6]))
print(counting_sort_offset([6005, 6001, 7000, 6005]))  # offset saves ~6000 slots

Q2 — money ($0.05 … $100): only 8 distinct values → counting array of length 8, not 10001. Build two-way map value↔index (sorted unique list), count by index, expand by index. Floats never index directly (precision) — map via dict or cents.

Python — Q2 money version (reads lotsOfMoney.txt)
def counting_sort_money(a):
    uniq = sorted(set(a))                 # e.g. [0.05, 0.1, 0.25, 1.0, 2.0, ...]
    to_i = {v: i for i, v in enumerate(uniq)}
    cnt = [0] * len(uniq)
    for x in a:
        cnt[to_i[x]] += 1
    out = []
    for i, c in enumerate(cnt):
        out.extend([uniq[i]] * c)
    return out

Micro-optimizations

Small changes, big speedups. Per-sort tricks live on each sort card — these are the cross-cutting ones plus the ones your handouts reward.

Course handout favourites (write these on the test)

Bubble: swapped flag → O(n) best case

A1/A4 stop after a swap-free pass. A2/A3 can't. One boolean saves n−2 passes on sorted input.

Bubble: shrink the bound (L++ / n−−)

Tail is final — never compare it again. Cuts ~n²/2 wasted comparisons.

Bubble: cocktail (bidirectional) for turtles

A tiny value at the end needs n passes one-directional, 1 pass bidirectional. Alternate directions (A4).

Selection: one swap per pass

n−1 writes total. Best when writes are expensive (flash / EEPROM).

Insertion: shift, don't swap

3 writes per swap → 1 write per shift + 1 insert. Use binary search for the insert point on long prefixes.

Counting: offset (min) kills waste

6000–7000 needs 1001 slots with offset, 7001 without, and is impossible with negatives without offset.

Counting money: dictionary map, not value-as-index

8 unique bills → 8 counters. Never use floats as indexes; map value↔index.

Counting stable: prefix sums

Turn counts into positions; place from the right. Required for radix sort.

Homework variant cheat-sheet

Bubble A1 vs A2/A3

Same: adjacent swap, in-place, stable. Different: A1 has swapped-flag + shrinking bound (adaptive); A2/A3 always run all passes.

Bubble A4 (cocktail) vs others

Same: adjacent swap core. Different: bidirectional passes; fixes turtles; both ends shrink.

Euclid mod vs subtractive

Same: GCD result, loop invariant. Different: mod = O(log n) jumps; subtractive = O(n) peels. Tiles: strip vs single row.

Powers naive vs fast

Same: xⁿ result. Different: O(n) mults vs O(log n) square-and-multiply; extra list + backward walk.

Selection out vs in

Same: min-select, O(n²). Different: O(n) extra list + remove/append vs O(1) in-place swaps.

Comparison vs counting

Same: both sort. Different: comparisons work on anything (Ω(n log n)); counting needs integer range but is O(n+k) linear.

Key takeaways

Comparison vs. non-comparison

Comparison sorts are general but bounded by Ω(n log n). Counting / radix beat it by exploiting key structure — only for suitable keys.

Stability

Merge, insertion, bubble, counting, radix: stable. Quick, heap, selection, shell: not (standard). Matters for multi-key sorts.

In-place vs. extra memory

Heap/quick/insertion/selection/bubble/shell: in-place. Merge O(n); counting/radix O(k)/O(n+k).

Adaptivity

Insertion + bubble-with-flag: great nearly-sorted. Selection + heap: always same work.

Worst-case guarantees

Merge + heap: O(n log n) guaranteed. Quick: O(n²) without good pivot. Counting/radix: linear in model.

Cache & constants

Quicksort wins on random data via locality + tiny constants. Big-O isn't the whole story.

Which sort when?

Small arrays (n < ~50)

Insertion sort — low overhead, adaptive, stable.

General purpose in-memory

Introsort (C++ std::sort) or Timsort (Python/Java) — hybrid, fast, robust.

Linked lists

Merge sort — stable, O(n log n), no random access needed.

Memory-constrained

Heap sort — guaranteed O(n log n), O(1) space.

Integers in small range

Counting sort — O(n+k) linear. Negatives? offset. Sparse huge range? don't.

Fixed-width integers/strings

Radix sort — O(d(n+k)).

Nearly sorted stream

Insertion sort or Timsort — adaptive, online.

External (disk-based)

External merge sort — chunks + k-way merge.
