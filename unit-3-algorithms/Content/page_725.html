Question 1

The Counting Sort works great for positive integers. However the following scenarios pose a problem.

Scenario 1.  Lists with negative integers.
This is a problem because negative numbers cannot directly translate to an index in a list.  Value != Index

Solution ...
Use an offset formula to translate the value to an index.


New Algorithm

calculate min and max of given list
spread  <--- max - min
offset_value <--- min

create the key or counting array based on spread

for each element in list
     index <--- element - offset_value
     increase counting array at index +1

for each index in counting array
     counter <--- value at index
     while counter is non-zero
          value <--- index + offset_value
          restore value to sorted list
          decrease count by 1

Question 2

Create a new version of the Counting Sort that handles a small selection of values for example money. $0.05 $0.10 $0.25 $1.00 $2.00 $5.00 etc ...

Read in the list of money values from the attached file.
lotsOfMoney.txt

Solution ...
Only have enough indexes for values you wish to store.
If there are 8 different $$$ values to store, then there should only be 8 zeros in the counting array.
Create a tool to translate $$$ amount to index in counting array.
Create a tool to translate index in counting array back to $$$


New Algorithm

identify the number of unique $$$ values in the list
for index from 0 to length of unique $$$ value list
     save index : $$$ value 
     save $$$ value : index


create the key or counting array based on number of unique values in the list

for each element in list
     index <--- element
     increase counting array at index +1

for each index in counting array
     counter <--- value at index
     while counter is non-zero
          element <--- index
          restore element to sorted list
          decrease count by 1
